## 1. 封面
- BF Market — AI agent 按次付费的服务市场
- 一句话：agent 读一个 URL，就学会自己付钱。
- 现场链接：https://market-fuji.bflabs.app
- 副标：Live on Avalanche Fuji · x402 v2 · Permit2

## 2. 问题
- agent 要买东西，但它没有账号、没有信用卡、没人替它点确认。
- 传统订阅和 API key 都要求先有人注册、先充值、先绑定。
- 结论：agent 经济缺的不是模型能力，是"两个互不相识的机器之间怎么结账"。

## 3. 产品
- 一个可复制的提示词，agent 读完 `skill.md` 就会用。
- 四步：发现服务 → 402 报价 → 签授权 → 拿到结果，收据公开。
- 三种入口：`skill.md`、MCP、discovery 接口。
- 证据：首页截图 + `skill.md` 里那句提示词。

## 4. 为什么必须是链
- 买卖双方没有共同账号系统，需要一个双方都能独立核对的结算层。
- 单次真实扣费 0.000168 USDC。手续费比付款贵的话，按次计费这个产品不成立。
- Avalanche Fuji：亚秒确认、极低 gas，支撑得起 6 位小数的按次定价。
- 这句话是全场最重要的价值主张，不要被技术细节盖过。

## 5. 两种计价，重点是 upto
- exact：固定价，签多少扣多少（echo 服务，1 USDC）。
- upto：**先签上限，后按实际用量结算**。报价 0.019040，实际扣 0.000168。
- 为什么关键：大模型这类服务的价格只有跑完才知道。买家签的是天花板，付的是地板。
- 证据：两笔收据截图 + 两条 snowtrace 交易链接。

## 6. 案例：agent 买它没有的能力
- 剪辑 agent 能写代码出片，但看不了成片。它去 BF Market，按描述找到 Gemini 3.8 Flash 视频理解服务，按次付费审片。
- 片子：20 秒「鹈鹕骑自行车」，代码逐帧绘制，没用生图模型。
- 四轮：审片 → 改片 → 再审。v1 指出刹车看不出、鱼没吞下、广告牌像浮窗；v4 四个节拍全部读出。
- 四笔 Fuji 结算，合计 0.018508 USDC，报价上限每次 0.0386。
- 诚实一句：模型约每秒一帧，会漏看不到 1 秒的动作，证据文件标出了它看错的地方。按次付费的意义就是 agent 付得起再问一次。
- 证据：v1/v4 关键帧对比 + 四条 snowtrace 链接 + 成片链接。

## 7. 技术复杂度
- 自托管 facilitator：官方托管服务不覆盖这条链，所以平台自己验证并广播结算。
- 广播前先持久化签名交易；每笔付款有幂等键；等到最终性才报成功。
- 一个 Durable Object 串行执行，幂等锁、签名 nonce、预算预占不可能竞争。
- 预占 → 按实际用量收缩 → 失败释放，三步都在一个事务里。

## 8. 安全与限额
- 平台从不持有买家私钥，只付结算 gas；钱从买家直达服务商收款地址。
- 每日预算：owner 给名下 agent 设上限，agent 只能往下调，生效值取较小者。
- 控制台公开只读：任何人输入地址就能看花了多少、收据是什么，不用连接钱包。
- 一句话立场：一个有钱包但没人管的 agent 是风险，预算是产品的一部分。

## 9. 已上线的事实（不要念清单，指屏幕）
- 线上：https://market-fuji.bflabs.app，五个服务在卖（含视频理解）。
- provider agent 253 已在 ERC-8004 官方注册表上注册。
- 真实付费调用已结算：exact 1 USDC、upto 0.000168 USDC，加四轮视频审片共 0.018508 USDC。
- 本轮没有部署任何合约——Permit2、两个 x402 代理、官方 ERC-8004 注册表 Fuji 上本来就有。

## 10. 可移植性
- 同一套代码同时跑在 BOT Chain 测试网（market.bflabs.app）和 Avalanche Fuji。
- 换链只改一个网络 profile 加一个部署配置，产品代码不变。
- 这回答了"你是不是只能跑一条链"：结算层与链解耦，是我们架构里主动做的选择。

## 11. 边界与下一步
- 诚实先说边界：两次调用的验收、单服务商、测试资金、无主网、无平台抽成。
- 下一步：服务商上架审核、平台抽成、AA 智能合约钱包限额、把按次付费接到真实业务量。
- 收尾一句：agent 会自己付钱这件事，今天已经在 Fuji 上跑通了。
